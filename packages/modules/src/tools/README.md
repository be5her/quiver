# Tools

Small converters that need no workspace: JSON format (pretty-print with a chosen indent, sort keys, or minify), JWT (header, payload and expiry, and validated against a key the way a server does), base64 encode and decode (standard or URL-safe), URL encode and decode, hash, UUID, timestamp, QR code and a DNS lookup. Each opens in its own tab from the sidebar or the command palette; most run on every keystroke.

## How it works

Every tool is a global command (`tools.json.format`, `tools.json.minify`, `tools.jwt.decode`, `tools.jwt.verify`, `tools.base64.encode`, `tools.base64.decode`, `tools.url.encode`, `tools.url.decode`, `tools.hash.digest`, `tools.uuid.generate`, `tools.timestamp.convert`, `tools.qr.encode`, `tools.dns.lookup`) with a zod schema, so the same conversions are available from the palette and to agents. Nothing is stored.

The JWT tab decodes the token as it is pasted, on its own or as an Authorization header value (`Bearer <token>`, the `jwt <token>` scheme some APIs use, or the whole `Authorization: …` line). Put a key in "Validate with" and it runs `tools.jwt.verify` instead, which validates the token as a server would and says above the output whether it is valid, and if not, why:

- the signature, against the key;
- `exp` and `nbf`, allowing "Clock skew" seconds either way (0 by default; ASP.NET's JwtBearer allows 300, many services 30);
- `iss`, when "Issuer" is filled in;
- `aud`, when "Audience" is filled in: the token passes when its `aud` is that audience, or an array that includes it.

The key can be the shared secret for HS256, HS384 and HS512 (tick "Secret is base64" when it is stored that way), or a public key, private key or certificate for RS, PS, ES (P-256, P-384, P-521, secp256k1) and EdDSA (Ed25519, Ed448): as PEM; as a base64-wrapped PEM, the form an environment variable often carries one in (`LS0tLS1CRUdJTi…`); as bare base64 DER (Keycloak's realm public key, a JWK's `x5c` entry); as a JWK; or as a JWK set, matched on the token's `kid` or tried key by key when it has none. A key is read by its bytes rather than its PEM label, so a certificate or a PKCS#1 key pasted under "BEGIN PUBLIC KEY" works, and so does a PEM copied out of a JSON or .env value with its line breaks written as `\n`. In the result, `valid` is the verdict, `problems` lists what failed, and `signatureValid` is the signature alone. A key that cannot check the token's algorithm is refused rather than reported as a mismatch, including a public key offered for an HS token (the algorithm confusion attack), and so is `alg: none`. The checks run on Node's crypto (`verifyJwt` in `@quiver/core/node`), with no dependency.

### QR code

The QR code tab encodes the text as it is typed and draws the symbol on a white tile, dark on light in both themes so a phone can scan it off the screen, with the version, size, mode and level under it. The header picks the error correction level (L, M, Q or H: 7, 15, 25 or 30 % of the symbol can be restored; M by default), the quiet zone in modules (4 by default, 0 to 8) and the pixels per module (8 by default, 1 to 32). **Copy SVG** copies the SVG; **Save PNG…** draws the matrix onto a canvas, black on white at that module size and margin, and writes it through the save dialog and `api.response.save`, so it needs an open workspace.

`tools.qr.encode` `{ text, errorCorrection?, margin?, moduleSize? }` returns `svg` (one `<path>` with a unit square per dark module, `fill="currentColor"` and `shape-rendering="crispEdges"`, the light modules transparent), `modules` (one string per row, `1` dark and `0` light, without the quiet zone), `version`, `size` (17 + 4 × version), `errorCorrection` and `mode`. The encoder (`encodeQr` and `renderQrSvg` in `@quiver/core`, `packages/core/src/qr.ts`) follows ISO/IEC 18004 with no dependency, one function per stage: the densest single mode that holds the text (numeric, alphanumeric, or byte as UTF-8; no kanji mode and no mixed segments), the smallest version that fits at the level, Reed–Solomon error correction over GF(256) in the standard's blocks, interleaving, the finder, timing and alignment patterns and the dark module, all eight masks scored by the penalty rules with the lowest kept, then the format and version information. Text is refused when empty, longer than 2953 bytes (what version 40 holds at level L), or too long for the chosen level, in which case the refusal names what that level holds in the text's mode (1273 bytes at H, for instance).

### DNS lookup

The DNS lookup tab takes a name, a resolver (empty for the system's) and the record types to ask for, A, AAAA, CNAME, MX, NS, TXT, SOA and CAA ticked by default, SRV, PTR and ANY on request. Enter or Lookup runs it; it is not live, since every lookup is a network call. Above the results it shows the CNAME chain when the name is an alias (`www.example.com → edge.example.net → example.net`), the resolver used and the time taken; below, one table per type with the name, the TTL and the record's fields (MX sorted by priority, SRV by priority and then weight), or "No records", "No such name (NXDOMAIN)" or the error for that type.

`tools.dns.lookup` runs on `node:dns/promises`: one `Resolver` per call, pointed at `server` when one is given, with two tries of half the call's timeout each (`timeoutMs`, 500 to 20000, 5000 by default) and a deadline at `timeoutMs` that cancels whatever is still unanswered, so the whole lookup ends within it (c-ares doubles the timeout on a retry, so a per-try timeout alone would take several times longer); what the deadline cut off is reported as `ETIMEOUT`. The types run in parallel, beside a walk of the CNAME chain one alias at a time (at most 16 links), and come back in the order asked. Node reports a TTL for A and AAAA only (capped at the chain's lowest TTL when the name is an alias); the other types have `ttl: null`. Records of the other types belong to the end of the chain, since the resolver follows the alias for them. An IP address is looked up in reverse instead (PTR on its `in-addr.arpa` or `ip6.arpa` name, with `reverse: { address, names }` in the result). ANY is sent as is; its answers keep their own type under `query: 'ANY'`, and a server that refuses ANY shows up as that type's error.

The name and the resolver are checked before anything is sent (`parseDnsName` and `parseDnsServer` in `packages/core/src/dns-lookup.ts`): the name is trimmed, loses one trailing dot, goes through IDNA (`url.domainToASCII`; the result carries both forms) and must be an IP address or a host name of at most 253 characters with labels of letters, digits, hyphens and underscores that do not start or end with a hyphen, so nothing option-like gets through. The resolver must be an IP address with an optional port (`1.1.1.1`, `1.1.1.1:53`, `[2606:4700:4700::1111]:53`); host names are refused, so nothing is looked up to find the resolver. "No records of this type" (`ENODATA`) and "no such name" (`ENOTFOUND`, NXDOMAIN) are answers, listed under `empty` per type; timeouts, refusals and server failures are listed under `errors` with a readable message. Each record is `{ query, type, name, ttl, data }`, `data` by type: `address`; `target` (CNAME, NS, PTR); `exchange` and `priority`; `entries` (TXT, one string per character-string); `nsname`, `hostmaster`, `serial`, `refresh`, `retry`, `expire`, `minttl`; `target`, `priority`, `weight` and `port` (SRV); `critical`, `tag` and `value` (CAA).

## Agents

Every tool is a pure conversion of its input and is allowed, `tools_jwt_verify` and `tools_qr_encode` included. `tools_dns_lookup` is allowed too: it only reads, sends DNS queries to the resolver named in the call (or the system's) and nothing else.

## Verified by

Unit tests sign tokens for every supported algorithm and check them against the right key, a wrong key, a tampered payload, a certificate, a JWK and a JWK set, read keys under the wrong PEM label or none, check expiry, not-before and the issuer with and without clock skew, check the audience as a string and as an array, and expect mismatched keys, `alg: none` and unreadable keys to be refused. One mirrors an auth server's contract: an RS256 token sent as `jwt <token>`, checked against the base64-wrapped public key with copy-paste whitespace in it, issuer pinned. The smoke verifies the jwt.io sample token against its secret and a wrong one, expects an agent offering a public key for it to be refused, validates an auth-server token against its base64-wrapped key (and fails it for another issuer or a required audience), and in the UI pastes the HS256 token with a secret, then the auth-server token with its key, issuer and an audience, into the JWT tab and reads the verdicts.

The QR encoder's unit tests reproduce a published symbol module by module ("HELLO WORLD" at 1-Q, mask 6), check mode detection, the edges of version 1-L in each mode, a larger version for each higher level, a 2000-byte text at version 33 with its finder and alignment patterns, the alignment centres of every version against Table E.1, the 2953-byte limit and the refusals, and the SVG's one square per dark module. To prove the symbols scan, they draw each matrix into a pixel buffer and read it back with `jsqr` (a dev dependency, used by the tests only): numeric, alphanumeric, UTF-8 (`héllo wörld ✓`), a 1 KB text, every level and every mask. The smoke encodes a URL and checks the square matrix, the three finder patterns and `size === 17 + 4 × version`, a larger version at H than at L, empty and oversized text refused, and an agent calling `tools_qr_encode`; in the UI it types the URL into the QR tab, counts the drawn squares against the matrix, reads the version line, saves a PNG (the save dialog answered by the smoke) and checks its pixel size, and switches to level H.

Unit tests for the DNS lookup cover the name (trailing dot, case, IDN both ways, IPv4 and IPv6, too long, a label over 63 characters, invalid characters, option-like and numeric names), the resolver (`ip`, `ip:port`, `[v6]`, `[v6]:port`, a bare IPv6 address, and host names, bad ports and malformed addresses refused), the reverse names, the CNAME chain from a list of answers (case, trailing dots, a loop), the error classification (ENODATA and ENOTFOUND empty, ETIMEOUT an error), and the ordering and grouping of records (MX, SRV, ANY). The smoke runs the lookup against a fake UDP DNS server on 127.0.0.1 (`src/main/smoke/fake-dns.ts`) with a small zone: every default type of `quiver.test` with the TTLs of A and AAAA, MX and SRV sorted, the two-link CNAME chain of `www.quiver.test`, the reverse lookup of 192.0.2.10, the reverse lookup of 2001:db8::10 under `ip6.arpa`, ENODATA and NXDOMAIN as empty per type (NXDOMAIN also when CNAME is the only type asked), a refused query and a timeout as errors (the timeout within `timeoutMs`), a host name as resolver and option-like names refused before any query is sent, and an agent calling `tools_dns_lookup`; in the UI it looks the alias up with SRV ticked through Enter and reads the chain, the resolver line and the tables, then `quiver.test` in the dark theme (SOA, TXT and CAA columns), a missing name (NXDOMAIN under every type) and a host name as resolver, and in a tab narrowed to 560 px the IPv6 reverse lookup and the SOA table wrap names between labels instead of scrolling sideways.

The smoke checks are in [`src/main/smoke/parts/tools.ts`](../../../../src/main/smoke/parts/tools.ts), which runs the sections [`tools/core.ts`](../../../../src/main/smoke/parts/tools/core.ts) (JSON and JWT), [`tools/qr.ts`](../../../../src/main/smoke/parts/tools/qr.ts) and [`tools/dns.ts`](../../../../src/main/smoke/parts/tools/dns.ts); `npm run smoke -- tools` runs them alone, with `--shots` for the UI checks.
